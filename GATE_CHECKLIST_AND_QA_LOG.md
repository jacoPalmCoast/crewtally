# Gate checklist and QA log (baseline 2.0)

Run this at the end of every phase. A phase isn't done until every box is ticked. "The Agent said it's done" is not a tick.

## 1. Tests on a fresh start
- [ ] The Agent pasted the summary lines of `npm run test:db`, `npm run test:server`, `npm run test:mobile` and, from Phase 1c, `npm run test:web`, with counts and zero failures. From Phase 8, `npm run test:release` too.
- [ ] The Agent restarted the API, Expo and (from 1c) the web app, and pasted clean startup lines.
- [ ] No test was skipped, deleted, loosened or marked `.only`. Ask: "List any test you changed or removed in this phase and why."
- [ ] Every provided database test still passes unchanged: `01`–`07` (from the start), `11` (from Phase 1b), `08`–`10` (from Phase 2). Agent-written files pass too: `12_receipts_statements` (P6), `13_deletion_jobs` (P7), `14_business_foundation` (B1), `15_business_work_states` (B2), `16_business_entitlements` (B4).
- [ ] The **role matrix** test ran, and its pass count went up by the routes this phase added. Ask for the rows added.

## 2. Proof, not prose
- [ ] Every item in the phase's "Proof to paste" section is pasted as real code or output.
- [ ] Anything the Agent calls "already done" has its code pasted.

## 3. Independent review (me)
- [ ] Pushed to GitHub from Replit's Git pane.
- [ ] Sent me the repo link and the phase number.
- [ ] I return **PASS**, or a findings list with severity (Blocker / Major / Minor).
- [ ] Every Blocker and Major is fixed and re-reviewed. Minor items are fixed, or recorded below as won't-fix with a reason.

What I check every time:
- every workspace route is registered with `memberRoute` and an action, reads the workspace from `X-Workspace-Id`, and calls `require_member` **in the same transaction** as its work (`withMember`);
- a non-member, a removed member and another workspace's ids get the same 404; a member without the right gets 403;
- the role matrix covers every route for organizer, partner, business owner, admin with and without money, lead, worker, removed member and outsider; until a B phase scopes a Home route, Business roles get 404 from its `kinds: ['HOME']` rule;
- nothing trusts a role, money flag, plan or owner id sent by a client;
- money writes go only through the database functions, and new money rows get `recorded_by` = the signed-in user (never null; a different supplied value → 403);
- every write takes an `operation_id` and uses `withWorkspaceIdempotency` or `withUserIdempotency`, with the signed-in user in the request hash;
- secret values were made by you in the Shell, never generated by the Agent in chat;
- partner limits hold: no rates, no removing people, no inviting, no plan, no deleting the workspace;
- no floats for money on any surface (web inputs parsed as text with integer math);
- migrations additive, checksum guard intact, provided functions unchanged;
- test bodies assert real values and failure cases, not just a 200;
- no secrets, names, emails, amounts, tokens or codes in logs;
- honest wording in the apps, PDFs, public pages and website ("Not bank verified" kept; never "Unlimited", "payroll", "verified", "sent" or "delivered" about money);
- the phase's must-not-build items each have a test.

Web-specific (from Phase 1c):
- [ ] Web writes need the session cookie **and** the CSRF header; a write without CSRF or from another Origin → 403 `CSRF_FAILED`.
- [ ] Web pages live at `/app/…`, workspace pages at `/app/w/:workspaceId/…`, and the workspace header comes from the URL.
- [ ] Nothing (records or drafts) is stored in the browser except the last used workspace id and the theme.
- [ ] The web shows the same errors and wording as the iPhone for the same action.
- [ ] No demo, design, role-switcher or "Reset sample" code exists in `web/src`.
- [ ] Public pages (`/api/r`, `/api/join`, `/api/go`) send `noindex`, `no-referrer`, `no-store` and the strict CSP, and never log tokens.
- [ ] From Phase 7: `/api/privacy`, `/api/support` and `/api/delete-account` redirect to the website pages. From Phase 8: only `/r/*`, `/join/*` and `/go/*` are forwarded to the API.
- [ ] From Phase 8: `npm run test:release` shows no developer sign-in in the release build; the review account path works only in production with both review Secrets set.

## 4. On your phone and on the web
- [ ] Every item in the phase's "Try it" list works, on the phone and on the web.
- [ ] At the largest iPhone text size, the new screens are usable.
- [ ] Dark mode on the new screens looks right, on both surfaces.
- [ ] Web, new pages: usable at phone width (390 px), tablet (768) and desktop (1440) with no sideways scroll; every action works with the keyboard alone, with visible focus; a screen reader reads labels and amounts.
- [ ] As the partner (member-c): the things a partner can't do are missing **and** refused by the server.

## 5. Decision
- [ ] Done → paste the next phase.
- [ ] Not done → paste the findings back to the Agent with: "Fix these findings. Keep all invariants in replit.md. Re-run the gate. Do not start the next phase."

### When the Agent gets stuck
- It's looping, or says it's done when the tests show otherwise: stop it, reload the page, and paste:
  > "Stop. Paste the current test output for every suite and `git status`. Do not change code until I reply."
- It wants to change `db/schema.sql`, an applied migration, a provided function (`role_can`, `require_member`, a money function, `fn_earned`, `delete_user_account`) or a provided test: the answer is no. (The one planned exception: B1's 0008 adds a Business guard to the three 0004 plan-limit trigger functions; that phase file is the approval.) Ask what problem it's trying to solve, and bring that to me.
- It wants to "temporarily" widen a permission, skip `require_member`, or trust a header to make something work: no.
- It offers extra features, or starts Business screens early: decline. "Stay in scope for this phase. Business stays behind BUSINESS_ENABLED=false."
